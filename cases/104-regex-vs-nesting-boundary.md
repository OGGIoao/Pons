## 场景

代码评审里有人提议："加个正则校验 JSON 嵌套括号吧。"这是该拦下的时刻——正则（有限自动机）只有有限个状态，没有记忆，永远数不了"任意深度的配对"。这不是正则不努力，是它在可计算层级里的位置决定了它做不到——正是图灵机卡片想建立的"能力边界"直觉。

## 信号

想用正则/有限状态解决"需要记住任意深度上下文"的问题——嵌套括号、匹配标签、同类配对——都是越界信号。判据很简单：解决这个问题需要多少"记忆"？固定层数可以硬编码，任意深度就需要栈，而栈的无限延伸正是图灵机超越有限自动机的那一步。

## 桥接

有限自动机：状态有限，读过的字符即刻遗忘；下推自动机（一叠无限长的纸带当栈用）：能配对任意深度的嵌套；图灵机：纸带可读写可回溯，表达一切可计算。三层能力，对应代码里的三个写法：正则 → 栈 → 完整模拟。解答里同一段校验，两个版本，边界立现。

## 解答

```python
import re

# 经典错误写法："首尾是括号就行"——它检查的是形状，不是配对
flawed = re.compile(r'\(.*\)', re.DOTALL)
trap = '((1)'          # 两个左括号一个右括号，根本不配对
print("形状正则放行未配对串？", bool(flawed.fullmatch(trap)))  # True——误报

# 有限自动机只有有限个状态、没有记忆，数不了"任意深度"的配对；
# 而一个栈（记忆的本质，图灵机的雏形）天然就是干这个的
def balanced(s: str) -> bool:
    depth = 0
    for ch in s:
        if ch == '(':
            depth += 1
        elif ch == ')':
            depth -= 1
            if depth < 0:
                return False           # 右括号抢先出现，立刻否决
    return depth == 0

assert not balanced(trap) and not balanced('(()') and not balanced(')(')
assert balanced('((()))') and balanced('()(())')
print("栈校验正确识别未闭合与乱序——正则做不到的事")
```
