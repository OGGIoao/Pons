## 🚩 阶段一：挑战

> **只看这个阶段，自己想 10 分钟。不要往下翻。**

### 场景：武林门派认定大会

武林中有 **100000 名侠客**，编号 1 到 100000。大会收到 **50000 条证言**，每条证言说「侠客甲与侠客乙是同门」。

同门关系有一个重要性质：**如果甲与乙同门、乙与丙同门，那么甲与丙也算同门**（可传递）。

证言全部录完之后，裁判要回答 **20000 次提问**：「侠客 X 和侠客 Y，是不是同门？」

**朴素的办法**：每次提问，从 X 出发顺着证言一层层找（BFS/DFS），最坏要扫全部 50000 条证言。20000 次提问 × 每次扫几万条 = 完全不可接受。

### 要你回答

1. 预处理证言时，能不能把「谁和谁同门」**提前整理好**，让每次提问几乎瞬间出答案？
2. 整理的关键是什么？（提示：一个门派几万人，其实只需要记录**一个**信息就能代表整个门派）
3. 把「整理 + 提问」写成算法——**合并两个门派时做什么？回答提问时做什么？**

> 💬 *先别急着翻。想想现实世界：怎么判断两个陌生人是不是同一个微信群的？你不需要认识群里所有人，只需要找到一个"共同的凭据"。这里面的"凭据"在算法里对应什么？*

**提示 1：把「门派」看成一个集合，每个集合只需要一个「代表」**

一个门派几万人，但我们不关心他们内部的结构——只关心「这两个人是不是同一个门派」。那就给每个门派选一个**代表**（比如编号最小的侠客），然后只记一件事：

```
侠客 → 他的门派的代表
判断 X 和 Y 是否同门 = 判断 representative(X) == representative(Y)
```

**提示 2：合并两个门派 = 让一个代表「归顺」另一个代表**

新证言说甲、乙同门，而甲属于门派 A（代表 ra），乙属于门派 B（代表 rb）：

```
让 ra 指向 rb（或反过来）
→ 从此 A 门派所有人的代表都顺着指针找到 rb
→ 两个门派变成一个
```

**提示 3：查找代表时，顺手把路「抄近道」**

如果代表关系是一条长链 `1 → 2 → 3 → ... → 99999`，每次查找都要走 99999 步。可以在查找的过程中让沿途的侠客**直接指向代表**：

```
查找 X 的代表时，把 X 路上经过的每一个节点的指针都改成指向代表
→ 下次再查这条路上的任何人，一步直达
```

**提示 4：合并时，小门派并入大门派**

合并时让**规模小的门派代表**指向规模大的，可以防止链条越来越深。两个技巧配合（提示 3 + 提示 4），每次操作几乎都只需常数步。

### 核心洞察

> **连通性是一种等价关系，而等价关系 = 集合。并查集就是给每个集合动态维护一个「代表元」的结构。**

只要一个问题能被描述成：

```
不断把元素合并成组，随时查询"两个元素是否在同一个组"
→ 每个组只存一个代表，合并 = 代表归顺代表，查询 = 找代表
```

一个统一的框架：

```
  {A}     {B}        {C}          ← 三个集合
代表:a   代表:b     代表:c
   \      /          |
    合并 A、B        查询(x, y)?
     ↓              = 代表(x) == 代表(y) ?
  {A ∪ B}
  代表:b
```

- **加边判断成环** = 边的两端是否已在同一集合
- **朋友圈/省份数量** = 数还剩几个集合
- **Kruskal 最小生成树** = 从小到大加边，不成环就收下

### 三步翻译——自己写代码

**第一步：说清意图**

```
写 find(parent, x)：返回 x 所在集合的代表元，顺手做路径压缩。
写 union(parent, rank, x, y)：合并两个集合，按秩合并；
    若本就同集返回 False，否则返回 True。
写 connected(parent, x, y)：判断两元素是否同集。
```

**第二步：拆成标准操作**

```
→ parent[i] = i 初始化：每人自成一派
→ find：沿 parent 指针一路向上，直到 parent[x] == x（找到代表）
→    沿途做路径压缩：parent[x] = parent[parent[x]]
→ union：ra, rb = find(x), find(y)
→    若 ra == rb：本就同门，返回 False
→    按秩（树高）把矮树挂到高树下，返回 True
→ connected：find(x) == find(y)
```

**第三步：匹配到代码**

| 标准操作 | 代码实现 |
|---------|---------|
| 初始化 | `parent = list(range(n))` |
| 查找代表 | `while parent[x] != x:` |
| 路径压缩 | `parent[x] = parent[parent[x]]` |
| 判断同集 | `if rx == ry: return False` |
| 按秩合并 | `if rank[rx] < rank[ry]: 交换` |

#### 🧪 自测用例

> 写完你的实现后，先跑这些用例（函数名可不同，逻辑对即可）。全通过后再看下面的参考实现。

```python
parent = list(range(5))
rank = [0] * 5

assert union(parent, rank, 0, 1) == True
assert union(parent, rank, 1, 2) == True
assert union(parent, rank, 3, 4) == True
assert connected(parent, 0, 2) == True     # 0-1-2 同一门派
assert connected(parent, 0, 3) == False    # 两个门派还没合并
assert union(parent, rank, 2, 3) == True   # 门派合并
assert connected(parent, 0, 4) == True
assert connected(parent, 1, 3) == True
assert union(parent, rank, 0, 4) == False  # 本就同门，返回 False
assert find(parent, 0) == find(parent, 4)  # 代表相同

# 规模测试：链式合并一万次后查询仍应瞬间完成
big_p = list(range(10000))
big_r = [0] * 10000
for i in range(1, 10000):
    union(big_p, big_r, i - 1, i)
assert connected(big_p, 0, 9999) == True
```

### 参考实现

```python
def find(parent, x):
    """查找 x 所在集合的代表元，顺带做路径压缩。"""
    while parent[x] != x:
        parent[x] = parent[parent[x]]  # 隔代压缩：指向爷爷，链条减半
        x = parent[x]
    return x

def union(parent, rank, x, y):
    """合并 x、y 所在集合（按秩合并）。本就同集返回 False。"""
    rx, ry = find(parent, x), find(parent, y)
    if rx == ry:
        return False
    if rank[rx] < rank[ry]:      # 保证 rx 是较高的一棵
        rx, ry = ry, rx
    parent[ry] = rx              # 矮树挂到高树下
    if rank[rx] == rank[ry]:
        rank[rx] += 1            # 同高合并，新根高度 +1
    return True

def connected(parent, x, y):
    """判断 x、y 是否属于同一集合。"""
    return find(parent, x) == find(parent, y)
```

**为什么这么快？** 路径压缩 + 按秩合并后，单次操作的均摊代价是 **O(α(n))**——α 是反阿克曼函数，增长慢到离谱：n 是宇宙原子总数时 α(n) 也不超过 5。工程上就当它是常数。

**一个易错点**：`find` 里务必写 `parent[x] = parent[parent[x]]`（隔代压缩）或递归版本，只走不压缩的裸 find 会被链式数据卡成 O(n)。

### 深度思考——「代表元」本质上是给集合命名

并查集最精妙的一步是**用代表元给整个集合命名**：集合里几万个元素，对外只用一个名字。于是「集合相等」这个 O(n) 的比较，被降维成「整数相等」这个 O(1) 的比较。这个「给集合命名」的技巧处处可见：

- **编译器**：判断两个类型表达式是否等价（类型合一）
- **数据库**：账户归并——发现两个账号是同一个人，合并余额与记录
- **图论**：Kruskal 每加一条边前问一次「两端是否已连通」

### 这个模式还出现在……

| 领域 | 问题 | 对应关系 |
|------|------|---------|
| **图论 · 最小生成树** | Kruskal：从小到大加边，跳过成环边 | union 返回 False 的边就是被跳过的 |
| **图论 · 连通分量** | 数「省份数量」「朋友圈个数」 | 数还剩多少个 parent[i] == i 的根 |
| **数组 · 最长连续序列** | LeetCode 128：未排序数组找最长连续段 | 把 x 与 x+1 合并，答案 = 最大集合大小 |
| **树 · 找环** | LeetCode 684：树多一条边，找出它 | 加边时两端已连通 → 这条边就是冗余 |
| **图像处理** | 连通域标记（给区域打标签） | 相邻像素 union，每个根就是一个区域 |
| **工程 · 账户归并** | 发现两个账号是同一人，合并数据 | union 两账号，查询归属 O(α(n)) |
| **编译器** | 类型等价判定、常量合并 | 等价类维护，同一代表 = 同一类型 |
