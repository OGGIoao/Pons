## 🚩 阶段一：挑战

> **只看这个阶段，自己想 10 分钟。不要往下翻。**

### 场景：定位那只「坏版本」

你的代码库有 **100000 个历史版本**，编号 1 到 100000。某一天，一个 bug 被悄悄引入了：

```
版本: 1  2  3  ...  k-1  k  k+1  ...  100000
状态: ✓  ✓  ✓      ✓   ✗   ✗         ✗
                     ↑
                  第一个坏版本 k
```

**关键性质**：bug 一旦引入就再也没修好——所以 `k` 之前全是好的，`k` 之后全是坏的。**单调**。

你手里有一个测试函数 `is_bad(v)`：输入版本号，返回它是否有 bug。但**每调用一次要跑 10 分钟**（完整回归测试）。

### 要你回答

1. 如果从版本 1 开始**一个一个试**，最坏要多少次？（显然 10 万次 = 太慢）
2. 利用「好/坏是单调的」这个性质，你**最少**需要测试几次就能精确定位 `k`？
3. 把这个「最少次数」的方法写成算法——**每次测哪一格？根据结果怎么缩小区间？**

> 💬 *先别急着翻。想想「猜数字」游戏：我心中有一个 1~100 的数，你每次猜一个数，我告诉你"大了/小了/对了"——你最快的策略是什么？定位坏版本和它是不是一回事？*

> **给自己最后一次机会——先试再想 5 分钟。还是没思路？逐条看提示。**

**提示 1：从「排除」的角度想**

线性扫描的问题是：每次测试只能排除**一个**版本。能不能让一次测试排除**一半**？

```
测试版本 v：
  如果 is_bad(v) == False → v 以及 v 左边全是好的 → 可以整段丢弃
  如果 is_bad(v) == True  → v 以及 v 右边全是坏的 → 也可以整段丢弃
```

**提示 2：维护一个「答案候选区间」**

始终维护区间 `[lo, hi]`，并保证一个**不变式**：

```
答案 k 一定落在 [lo, hi] 里
（lo 一定是好的，hi 一定是坏的，或它们的边界情况）
```

每次取**中点** `mid = (lo + hi) // 2`，测一次 `is_bad(mid)`，然后把区间缩小一半。

**提示 3：怎么缩？**

```
is_bad(mid) == False  →  k 在 mid 右边  →  lo = mid + 1
is_bad(mid) == True   →  k 在 mid 左边或就是 mid  →  hi = mid
```

> 注意：这里 `lo` 始终指向"还没排除"的左边界，`hi` 始终指向"可能是答案"的右边界。

**提示 4：什么时候停？为什么不会死循环？**

当 `lo == hi` 时，区间只剩一个位置——它就是答案。每次循环区间**至少减半**，所以最多 `⌈log₂(n)⌉` 次。100000 个版本，最多约 **17 次**（2¹⁷ ≈ 131072）。

### 核心洞察

> **二分搜索的本质不是「在有序数组里找某个数」，而是「在单调谓词上找边界」。**

只要一个问题能被描述成：

```
某个条件 P(x) 在左边为假、右边为真（单调）
→ 存在一个分界点，二分搜索用 O(log n) 次测试找到它
```

一个统一的框架：

```
[ 假 假 假 | 真 真 真 ]
            ↑
          边界（第一个"真"）
```

- **猜数字 / 找第一个坏版本** = 找「假 → 真」的边界
- **lower_bound（找第一个 ≥ target）** = 找「< target → ≥ target」的边界
- **求平方根、找峰值、答案二分** = 都是同一件事

### 三步翻译——自己写代码

**第一步：说清意图**

```
写 lower_bound(arr, target)：返回第一个 ≥ target 的下标。
再写 first_bad_version(n, is_bad)：返回第一个满足 is_bad 的版本号。
都维护区间 [lo, hi) 或 [lo, hi]，每次取中点缩小一半。
```

**第二步：拆成标准操作**

```
→ 初始化 lo = 0, hi = n（左闭右开 [lo, hi)）
→ while lo < hi:
    → mid = (lo + hi) // 2
    → 若 arr[mid] < target（还没到边界）→ lo = mid + 1
    → 否则（mid 已在边界右侧或就是边界）→ hi = mid
→ 返回 lo（第一个 ≥ target 的位置）
```

**第三步：匹配到代码**

| 标准操作 | 代码实现 |
|---------|---------|
| 初始化区间 | `lo, hi = 0, len(arr)` |
| 循环条件 | `while lo < hi:` |
| 取中点 | `mid = (lo + hi) // 2` |
| 缩小左边界 | `lo = mid + 1` |
| 缩小右边界 | `hi = mid` |
| 返回边界 | `return lo` |

### 参考实现

**写法 A——lower_bound（找第一个 ≥ target 的下标，左闭右开）**

```python
def lower_bound(arr: list[int], target: int) -> int:
    """返回第一个 >= target 的下标；若不存在返回 len(arr)。"""
    lo, hi = 0, len(arr)          # 不变式：答案在 [lo, hi)
    while lo < hi:
        mid = (lo + hi) // 2
        if arr[mid] < target:     # mid 还在"假"区
            lo = mid + 1
        else:                     # mid 已经在"真"区
            hi = mid
    return lo
```

**写法 B——first_bad_version（在单调谓词上找边界）**

```python
def first_bad_version(n: int, is_bad) -> int:
    """版本 1..n，is_bad(i) 单调（前假后真）。返回第一个坏版本。"""
    lo, hi = 1, n
    while lo < hi:
        mid = (lo + hi) // 2
        if is_bad(mid):
            hi = mid              # 答案在 mid 或左边
        else:
            lo = mid + 1          # 答案在 mid 右边
    return lo
```

**为什么不会死循环？** 每次 `lo < hi` 时，`mid = (lo+hi)//2` 一定满足 `lo ≤ mid < hi`，所以 `lo = mid+1` 或 `hi = mid` 都会让区间**严格变小**，最终 `lo == hi` 收敛。

### 深度思考——「二分」其实可以脱离「数组」

很多人以为二分搜索只能用在"已排序数组"上。但它真正的条件只有一个：**能定义单调谓词**。于是：

- 在**答案域**上二分：`is_good(x)` = "用 x 天能否完成所有任务" → 找最小的可行天数
- 在**实数域**上二分：求 √2 到 1e-9 精度，`is_good(x)` = "x² ≥ 2"
- 在**函数极值**上二分：单峰函数找峰值，`is_good(mid)` = "mid 右边比 mid 小"

### 这个模式还出现在……

| 领域 | 问题 | 对应关系 |
|------|------|---------|
| **版本控制** | 定位第一个引入 bug 的 commit | `git bisect` 就是自动化的二分 |
| **求平方根/开方** | 在答案域上二分逼近 | 谓词 = "x² ≥ n" |
| **调度 / 资源分配** | "最短时间完成所有任务" | 在时间域上二分 + 贪心判定可行性 |
| **数据库** | B+ 树索引的区间查找 | 底层就是不断二分定位到叶子 |
| **查找峰值** | 单峰数组找极值 | 比较 mid 与 mid+1 决定往哪边走 |
| **猜价格 / 猜数字游戏** | 用最少提问锁定目标 | 每次排除一半 |
